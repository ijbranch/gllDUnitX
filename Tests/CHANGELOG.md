## [In-Service]

### Added
- (2026-11-02) **Upstream #568's and #578's tests, ported as guards** — `DUnitX.Tests.TestFixture.pas`.  New fixture `TFixtureConstructorTests` (upstream's name) runs a fixture whose constructor raises (`TRunnerConstructorToggles`) or ignores beside one that passes, through the new `RunFixtures` helper (several fixtures in one run; `RunFixture` now calls it) and `ResultsText` (the whole run as one comparable string): its tests are errors of the constructor's class and message and the other fixture passes, with no test, `[Setup]`, `[TearDown]` or `[TearDownFixture]` run; an ignoring constructor gives ignored tests; an `[Ignore]`d test stays ignored; and a re-run whose constructor now succeeds runs tests, `[Setup]`, `[TearDown]` and `[TearDownFixture]` on the new instance.  Upstream's parallel case (`-m:4`) is not ported: this fork has no parallel fixture runner.  One deliberate difference: the constructor runs twice here (as the list is built, and again as the fixture runs), once upstream, which keeps the exception instead.  `TRunnerBehaviourTests.LoggingIsNotALeakAcrossSetupAndTearDown` adds #578's logging case with a setup and teardown around the test.  #578's between-phases and `Assert.Pass` cases were already covered (`LeakCheckIgnoresMemoryFreedBetweenPhases`, `LeakCheckCountsOnlyTheTestsOwnGrowth`); its logger-state case found a gap, fixed and recorded in the repository's `CHANGELOG.md`.  The tests in this entry passed first time and were mutation-proved: each fails on a mutant of the runner or fixture line it guards.  `LoggingIsNotALeakAcrossSetupAndTearDown` compares the logging test's message exactly (its log, once), as upstream does.
- (2026-11-02) **Upstream #561's fixture-setup cases, as a guard** — `DUnitX.Tests.TestFixture.pas`.  `TRunnerBehaviourTests.FixtureSetupRunsOnlyWhenATestWillExecute` counts `[SetupFixture]` / `[TearDownFixture]` calls and results for five fixtures: all tests ignored (0/0), one runnable (1/1), the runnable one disabled as a filter does (0/0), a `[RepeatTest]` beside ignored tests (1/1) and a `[RepeatTest]` alone (1/1).  **Why:** checking #561 against this fork before absorbing it; all five already pass here (this fork decides on enabled, non-ignored tests, and its repetitions count as the fixture's own), so nothing in Source changes.  Two mutants killed: running the setup regardless, and counting a disabled test.
- (2026-11-02) **A `[TestCase]` case still running at its `[MaxTime]` is interrupted** — `DUnitX.Tests.TestFixture.pas`.  `TMaxTimeInterruptTests.A_TestCase_Overrun_Is_Interrupted_And_Fails` builds a busy-looping case through the fixture provider and checks it fails with the timeout within half its uninterrupted time.  Mutation-proved: starting no timeout for a `TDUnitXTestCase` fails it.  **Why:** upstream's `TDUnitXTestCase` never starts a timeout (#544); here only a case sleeping past its `[MaxTime]` was tested, without checking how it was stopped.
- (2026-11-02) **The locale round trip writes the year in full** — `DUnitX.Tests.Utils.pas`.  `Date_And_Time_Formatted_In_The_Locale_Read_Back` turns a `yy` short date format into `yyyy` first: a user who set a two-digit year for the machine's own locale would make it write `22/06/20`, which by design no longer converts.  Found by the review of upstream PR #545.  Cannot be mutation-proved on a machine whose format already has `yyyy`.
- (2026-11-02) **Each `[RepeatTest]` repetition gets the `[Setup]` and `[TearDown]` of a base class, and those declared after the repeated method (upstream #479)** — `Tests/DUnitX.Tests.TestFixture.pas`.  `RepeatTest_Gets_The_Setup_And_TearDown_Of_A_Base_Class` and `RepeatTest_Gets_The_Setup_And_TearDown_Declared_After_It` count three Setups and three TearDowns for three repetitions, each repetition after its own Setup.  They passed on first run: this fork keeps repetitions in the fixture itself (`Source/DUnitX.FixtureProvider.pas`), so the copy-too-early fault upstream's `70cee9c` fixed never applied.  Upstream's own two #479 tests also assert that the repetitions form one child fixture, a structure this fork does not have, so they are not taken.
- (2026-10-26) **`README.md`: the suite's 9 ignored tests are listed, each with why** — `README.md`, `DUnitX.Tests.TestFixture.pas`.  All nine prove DUnitX honours `[Ignore]` or `[RepeatTest(0)]`; none pins a defect.  `TestTimeout`, the one with a blank reason in run reports, now carries its reason in the `[Ignore]` attribute.  **Why:** `verify_change` warns on every ignored test ("check each is listed in the suite README"); Ian asked for that check, 2026-10-26.
- (2026-10-25) **This change log** — `CHANGELOG.md`.  The suite's own record, per the estate rule that every test
  suite has one; test-only history moved in from `..\CHANGELOG.md` ( 9 entries ).
- (2026-10-12) **NaN tests for `Assert.AreEqual` / `AreNotEqual` on `Double` and `Extended`** —
  `Tests/DUnitX.Tests.Assert.pas`. Six tests: `AreEqual` must fail with NaN as either argument, and `AreNotEqual`
  must pass when one value is NaN. Prompted by the fork survey below (fabiorizzuto's 2018 fork adds an explicit
  `IsNan` check). **Result: no defect** — `System.Math.SameValue` already returns `False` for NaN, so all six pass on
  Win32 (x87 `Extended`) and Win64 with `Source/` unchanged. Mutation-proved: forcing the four `SameValue` sites in
  `Source/DUnitX.Assert.pas` to never fail / always fail turned all six red. The same run showed these are the
  ONLY tests of `AreNotEqual( Double / Extended )` raising: no older test failed under that mutation.

### Changed

- (2026-11-02) **`TestTimeout` runs instead of being ignored; every `TValueHelperTests` test restores the locale** — `DUnitX.Tests.TestFixture.pas`, `DUnitX.Tests.Utils.pas`, `README.md`.  `TestTimeout` expects its own interruption with `[WillRaise(ETimedOut)]`, which passes since the same day, so the suite reports 8 ignored tests, not 9; its body is now a busy loop bounded at 3 s, which the watchdog interrupts where it stands, instead of a `Sleep(150)` that is only interrupted when it returns (50 ms of slack against a 100 ms `[MaxTime]`, found by review).  `TValueHelperTests` restored `FormatSettings` only in its destructor, so a test that set no locale ran under whatever the last one left; a `[TearDown]` now restores it after each test (found by the port's review).
- (2026-10-26) **Unit-scope names in every `uses` clause** — `Tests/DUnitX.SingleNameSpace.pas`, `Tests/DUnitX.Tests.CommandLineParser.pas`, `Tests/DUnitX.Tests.TestFixture.pas`, `Tests/DUnitX.Tests.TestNameParser.pas`, `Tests/DUnitX.Tests.Utils.pas`, `Tests/DUnitXTestProject.dpr`.  8 bare RTL/VCL unit names in `uses` clauses given their unit-scope names, 1 partly-scoped name (`Generics.Collections`) completed, 1 scoped name respelt as the unit declares itself; generated code is byte-identical in every mode built.  **Why:** Ian, 2026-10-26: "all the gll* forks are our own code because they have all been modified to suite our needs/preferences/standards".  Divergence from upstream: a later upstream merge conflicts wherever upstream edits a converted `uses` line; resolve by taking upstream's change and keeping the scoped spelling.
